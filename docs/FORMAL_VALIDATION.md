# Formal Validation

Stage 5 converts promising Stage-4 observations into prospective evidence without granting automatic policy authority.

## Protocol

The freeze is written before prospective source generation. It binds the Stage-3 programs, Stage-4 research state, position-value model, benchmark index, registry hash, evidence policy, candidate domains, source exclusions, environments, sample targets, and statistical gate.

Clean manager rules are grouped only when at least two managers independently support the same action domain, no non-neutral Stage-4 contradiction exists for those rules, and every rule implies the same intervention direction. The delivered freeze contains hazard, physical attack, special attack, and switch domains.

Two declared environments use different profile allocation schedules and independent semantic battle seeds. Every source has a complete formal evidence context. A battle may supply at most one planned intervention across the entire family. Stage-4 discovery fingerprints are excluded.

Each primary case receives one preregistered fallback from a different battle. A fallback may be used only after an exact replay or intervention integrity failure. Source, prefix, and intervention verification must all be true before a result can enter the completed set or case cache. A competitive result can never trigger replacement.

## Gate

Each domain requires:

- 24 exact cases, with at least 12 from each environment;
- at least six interventions that change the winner;
- more supporting than contradicting winner changes in every environment;
- a one-sided exact sign test that survives Holm correction across all frozen domains at familywise alpha 0.10;
- no unresolved technical failure, source drift, prefix drift, duplicate battle, or discovery leakage.

Passing produces `limited-canary-eligible`. It does not edit a manager program or enable a policy. Rejection, inconclusive evidence, and technical blocking are distinct outcomes.

## Commands

```powershell
npm run formal-validation -- cycle
npm run formal-validation -- status
npm run formal-validation -- doctor
npm run formal-validation -- doctor --verify-sources
npm run formal-validation -- inspect --domain battle-switch
```

The cycle is resumable. Source manifests, the frontier, signed plan, case cache, compressed results, run state, failure list, and compact token budget are retained locally. Cached cases are reused only after their source, action, environment, and expected-direction bindings match the signed plan. Doctor reconstructs plan coverage from the frozen frontier, validates one result per planned case, and recomputes the summary. After execution, decision traces and battle logs are atomically gzip-compressed. Doctor hashes their decompressed semantic bytes, so storage compaction does not weaken source verification or replay support.
