# White-box AI rollout

Tactical opponent-memory benefit is evaluated by an exact single-side ablation sampler. The first V14 calibration selected a `.15` confidence-floor hypothesis without activating it. A separate three-journey holdout then found that low-confidence memory produced 1 improvement and 9 regressions across 10 decisive exact-seed clusters (`p=0.0107` for regression). New journeys therefore retain low-confidence evidence but do not let it influence battle choices until confidence reaches `.15`. Cumulative and seasonal-decay behavior memories now update in parallel from the same episodes, and compact named shadows enter replay capsules without affecting live choices. A 121-pair, 53-seed seasonal-decay holdout found 0 improvements and 4 regressions, but only two directional seed clusters; its `insufficient-evidence` conclusion keeps cumulative behavior memory active. A separate standard ablation above the floor found 4 improvements and 6 regressions with evenly split directional seed clusters, establishing behavioral impact but `no-clear-benefit`. See `docs/TACTICAL_MEMORY_ABLATION.md`.

The white-box route is introduced as an observable layer around the stable V13 AI. It must not silently change league behavior before fixed-seed and long-run validation.

## Rollout order

1. `shadow`: record what the white-box core would choose while V13 remains authoritative.
2. `assist`: use reports to tune semantic rules and eliminate duplicated features; V13 still acts.
3. `active`: promote one bounded decision domain only after fixed-fixture, paired-seed, and long-run checks pass.

Lineup and keeper traces retain a compact top-candidate audit plus the incumbent and shadow winner, avoiding large ledger entries for every possible combination. Auction traces record the exact bid arithmetic alongside the incumbent bid; they do not change the winner. Cross-season planning, case libraries, active league direction, and automatic parameter optimization remain out of scope until a measured need appears.

## Unified audit

Run `npm run audit:whitebox -- --out <league-output>` against either one V3 season directory or a V4-V12 dynasty root. The command writes `whitebox-audit-summary.json` and `whitebox-audit-report.md` inside the output directory.

- `blocked`: missing traces, invalid arithmetic, non-finite values, parameter-bound violations, rollback drift, or less than 98% trace coverage.
- `needs-review`: structurally valid output whose incumbent/shadow agreement is below 98%.
- `shadow-stable`: no fatal issue, at least 98% coverage, and at least 98% incumbent/shadow agreement. This is evidence for continued shadow operation, not automatic authorization to activate the white-box policy.

## Fixed-seed soak

Run `npm run soak:whitebox -- --run --out output/whitebox-soak --seeds whitebox-soak-a,whitebox-soak-b --repeats 2 --seasons 2`. Existing run directories are preserved unless `--force` is explicitly supplied. Without `--run`, the command rescans existing `soak-run.json` metadata and rebuilds the aggregate report.

The first repeat of each seed is the practical baseline. Promotion requires repeated runs to match both the essential league-outcome digest and the complete audit-summary digest; therefore a stable champion with drifting intermediate traces is still blocked. Coverage below 98% is fatal, incumbent/shadow agreement below 98% needs review, and audit payload above 25% of total output needs review. Per-run shadow disagreements remain visible in `auditWarnings` even when the aggregate agreement gate passes.

## Assist review

Run `npm run review:whitebox -- --out <league-output>` to write `whitebox-differences.json` and `whitebox-differences.md`. The report extracts decision-level disagreements and performs a one-step counterfactual comparison over legality, rational score, bounded style score, final score, member additions/removals, and every changed contribution.

Cases are classified as `reasonable-style-choice`, `rational-correction`, `illegal-incumbent`, or `missing-candidate`. A reasonable style choice is evidence of a deliberate personality/economic trade-off, not by itself a defect. New keeper review records also retain `keeperWhiteBoxCounterfactual`, containing the exact alternate contracts and releases needed for a later isolated season-branch replay. This payload remains observational and does not replace the incumbent keeper list.

## Cross-season counterfactual

Run `npm run counterfactual:whitebox -- --source <league-output> --out <experiment-output> --case-index 1 --followup-seasons 1`. The command deterministically replays two complete branches from identical initial conditions. The incumbent branch retains normal behavior; the white-box branch activates the alternate keeper portfolio only for the selected manager and review season, then returns to normal behavior.

The runner verifies that the incumbent history reproduces the complete source prefix and that the white-box history reproduces the source through the intervention season. It then compares cash, payroll, contract count, points, rank, titles, and subsequent champions. Existing experiment directories are never replaced unless `--force` is explicit. This is an experimental activation path only; ordinary V12 runs remain in shadow mode.

Aggregate completed experiments with `npm run counterfactual:whitebox-batch -- --inputs <experiment-a>,<experiment-b> --out output/whitebox-counterfactual-batch`. The aggregate report separates competitive direction from financial savings and reports paired win rate plus mean deltas. The default evidence gate requires at least ten paired cases and five independent seeds; smaller batches always remain `insufficient-evidence`, even when every observed case points in the same direction.

Use `npm run counterfactual:whitebox-sample -- --run --out output/whitebox-counterfactual-sampler --existing <experiment-a>,<experiment-b> --target-samples 10 --minimum-seeds 5` to automate evidence collection. Each candidate seed first runs a compact two-season baseline. Seeds without a keeper disagreement are recorded and skipped; seeds with disagreements run at most one paired experiment. The manifest is written after every seed, so the same command can resume after interruption without repeating completed work. The default output ceiling is 1024 MB and can be lowered with `--max-output-mb`. Smaller targets are allowed for workflow testing, but the promotion gate has a hard floor of ten paired cases and five independent seeds.
